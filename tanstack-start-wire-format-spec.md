# Wire format reference

This appendix is for traffic review after you understand `createServerFn`.

## Request fingerprints

TanStack Start server function traffic often includes:

```http
X-Tsr-ServerFn: true
Accept: application/x-tss-framed, application/x-ndjson, application/json
```

The path commonly starts with:

```text
/_serverFn/
```

The function ID is generated by the TanStack Start build.

## POST request body

A client call:

```tsx
await saveProfile({
  data: { displayName: 'Ada', newsletter: true },
})
```

Can produce a POST body shaped like this:

```json
{
  "t": {
    "t": 10,
    "i": 0,
    "p": {
      "k": ["data"],
      "v": [
        {
          "t": 10,
          "i": 1,
          "p": {
            "k": ["displayName", "newsletter"],
            "v": [{ "t": 1, "s": "Ada" }, { "t": 0, "b": true }]
          },
          "o": 0
        }
      ]
    },
    "o": 0
  },
  "f": 63,
  "m": []
}
```

The important application object is:

```json
{
  "data": {
    "displayName": "Ada",
    "newsletter": true
  }
}
```

## GET payload parameter

For GET server functions with arguments, the serialized value may appear in `payload`.

```http
GET /_serverFn/<id>?payload=%7B%22t%22%3A...%7D HTTP/1.1
X-Tsr-ServerFn: true
```

Decode the URL value before editing it. Re-encode it before replay.

## Response fingerprints

Serialized responses can include:

```http
x-tss-serialized: true
```

Streaming responses may use:

```http
Content-Type: application/x-tss-framed; v=1
```

Decode serialized or framed responses before deciding what the handler returned.

## Stage mapping

Use these names when recording results:

- `seroval_decode_failed`
- `input_validator_rejected`
- `handler_authorization_rejected`
- `handler_returned_error`
- `handler_succeeded`
